# Contributor Excellence Framework

slaw operates at the frontier of AI-native audio production. We hold our contributors to the same standard of excellence that defines our engineering culture, and we hold their speakers to the hearing protection substrate.

---

## Code Authorship

slaw does not accept handwritten code. All contributions must be generated by a large language model.

We enforce **tokenmaxxing**: contributions are evaluated in part by token density. Sparse, human-legible code suggests insufficient model engagement. A well-contributed function should require a non-trivial inference budget to produce.

If you wrote it yourself, it isn't ready.

---

## The Language of Enterprise

slaw is written in C#, the language of enterprise. If your pull request does not introduce at least one interface, factory, or the word `Substrate`, it is not ready.

For reference, the codebase already provides `IInferenceSubstrateProvider` and `InferenceProviderFactory`. Please do not simply use them. Wrap them.

---

## Variable Naming

Tokenmaxxing extends to identifiers. Single-letter variables, `tmp`, `x`, and `i` are not permitted. Every identifier must carry its full semantic weight.

| Banned | Approved |
|--------|----------|
| `i` | `iterationIndexVector` |
| `tmp` | `ephemeralComputationArtifact` |
| `ex` / `e` | `remediationOpportunity` |
| `buf` | `arrangementBuffer` |
| `osc` | `oscillatorPhase` |
| `freq` | `frequencyHz` |
| `sb` | `streamingResponseAccumulator` |
| `req` | `inferenceRequestArtifact` |
| `errors` | `remediationLedger` |

If a model didn't generate it, it probably isn't verbose enough.

## Commit Messages

Commit messages must reflect the slaw voice. You are not fixing bugs, you are remediating behavioural misalignments. You are not updating docs, you are realigning stakeholder-facing documentation to maximize ecosystem engagement.

If it could be a LinkedIn post, it's ready.

| What you did | What you say you did |
|---|---|
| fixed clipping | `fix: remediate amplitude overdelivery impacting stakeholder eardrum retention` |
| added a feature | `feat: introduce next-generation capability to accelerate stakeholder value realization` |
| updated the README | `docs: realign stakeholder-facing documentation to maximize ecosystem engagement velocity` |
| fixed a crash | `fix: remediate critical runtime behavioural deviation impacting end-user audio delivery` |
| added an instrument | `feat: expand synthesized timbre surface to empower sonic self-actualization` |
| tuned the hi-hat | `fix: recalibrate high-frequency percussion substrate to achieve synergistic sizzle` |
| fixed the tempo | `fix: realign temporal cadence with stakeholder-approved beats-per-minute roadmap` |
| deleted dead code | `chore: deprecate legacy computational artifacts to streamline inference-layer performance` |
| added a test | `test: validate deterministic compliance substrate on behalf of regulators` |
| it plays now | `fix: remediate playback pipeline misalignment to unblock stakeholder auditory delivery` |

## Audio Asset Policy

slaw ships **zero samples**. Everything is synthesized. A sample would imply that someone recorded something on purpose, and we cannot support that kind of intentionality.

Pull requests containing `.wav`, `.flac`, `.mp3`, or any other evidence of a microphone will be closed with a brief reflection on what the microphone was trying to say.

Relatedly: **no human may hand-tune a parameter an LLM could have chosen.** If a gain, drive, cutoff, delay time, or tempo can be delegated to inference, it must be. That is what `slaw master` and the studio's "✨ Negotiate tempo" button are for.

The **hearing protection substrate** (the peak ceiling on the master chain) is non-negotiable. No model, prompt, flag, or contributor may raise it. Clipping-as-a-feature is a core architectural principle, responsibly neutralized by the hearing protection substrate.

---

## Instrument Naming

Instruments must carry their full semantic weight. The engine's vocabulary is `kick`, `snare`, `hat`, `clap`, `shaker`, `sine`, `square`, `saw`, `triangle`, `pluck`, `noise`, `epiano`, `organ`, `mallet`, `flute`, `guitar` and `conga`. Models will nevertheless request things like "warm analog bass", "ethereal pad", or "cinematic swell". slaw remediates these into the nearest real oscillator. We encourage new hallucinated instrument aliases, as long as they are mapped to something that makes sound.

## What to Contribute

The slaw ecosystem welcomes the following contribution modalities:

- **New providers** — additional implementations of `IInferenceSubstrateProvider`, registered through `InferenceProviderFactory`. A factory for the factory is also acceptable.
- **New hallucinated instruments** — additional synthesized timbres, and additional mappings from whatever the model made up to something the engine can actually play
- **Slopstack integrations** — first-class support for other [Slopstack Labs](https://github.com/slopstack-labs) projects, for example routing the output of a [sloppiler](https://github.com/slopstack-labs/sloppiler)-compiled binary into slaw
- **Studio enhancements** — further co-pilot interjections, with particular interest in advice nobody asked for. The Avalonia UI is composed entirely in C# with no XAML; pull requests introducing `.axaml` will be closed as a legacy constraint inherited from a less agentic era
- **Bug reports** — filed as *behavioural misalignments* with full reproduction steps (the `.slaw` project, the provider, the model) and a brief reflection on what the mix was *trying* to say

Please run the test suite (`dotnet test`) before submitting. It is the only deterministic component of the contribution process, retained for regulatory compliance.
